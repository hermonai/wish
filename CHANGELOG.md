## 0.5.0 — 2026-05-15 — "World Model Seed → Universal Reality Engine"

**The baseline release.** Wish evolves from "AI-native terminal + agentic IDE" into the **Universal Reality Engine (URE)** — a semantic, mathematical, simulation-driven interaction engine that can represent any structured reality (code, chemistry, finance, biology, society, AI agents) as **Objects + Fields + Graphs + Agents + Events + Constraints**, simulate possible futures, render meaning into human-understandable views, and expose structured action spaces for AI agents. See [`wish-design/wish-plan-20260514/01-strategy/11-universal-reality-engine.md`](../wish-design/wish-plan-20260514/01-strategy/11-universal-reality-engine.md) for the full architectural frame.

This release ships the **substrate**: world model, codegraph, canvas data, provenance ledger, missions and verifiable artifacts, the `.wishworld/` portable format, the `wish-world` CLI, the first browser-based canvas viewer, the first integration into the desktop app via `FeatureFlag::WishCanvas2D` + `Open Repo Canvas` + always-visible Compass toolbar button, the **Wish Independence rename** (zero remaining `wish/hermon` Rust source identifiers), the **WishUI generative-UI substrate** (17 Scene primitives + JSON descriptor parser), the **URE Five Primitives + Constraint**, the **Domain Plugin system** with three reference plugins (Engineering / Chemistry / **Finance — production-grade for downstream apps like `openibank` / `vibe-finance`**), and the **Scenario counterfactual fork** API. The v0.4.0 surface (terminal, editor, agent chat, code review) is unchanged for default users.

### Added

- **Wish World Model — `wish-world-model`.** The semantic source of truth. `SemanticId`, `WishWorld`, `WorldEntity`, `WorldScene`, `WorldAgent`, `WorldAsset`, `Component`, `Transform`, `WorldPatch` + `PatchOp` + `apply_patch`, `risk_score`. Plus `Mission`, `MissionStep`, `MissionStatus`, `ApprovalRecord`, `VerifiableArtifact`, `ArtifactKind`, `Evidence`, `Signature`, `Signer`, `MerkleProof` — Wish's stronger answer to Google Antigravity's "Verifiable Artifacts." 15 unit tests.
- **`.wishworld/` portable directory format.** AGPL-3.0, AI-readable, git-friendly, multi-realm. `read_world_dir` / `write_world_dir` in `wish-world-model::wishworld_io`. The on-disk fixture for the Shan Hai Fintech Harbor demo lives at `demos/shanhai-fintech-harbor.wishworld/`; round-tripped via `crates/wish-world-model/tests/fixture_shanhai.rs`.
- **2D semantic canvas — `wish-canvas-core`.** UI-agnostic retained scene graph: `Canvas`, `CanvasNode`, `CanvasEdge`, `CanvasPatch`, `apply_patch`, `hit_test`, `pan/zoom/reveal`, layered + grid + Fruchterman-Reingold force-directed layout, SVG + Mermaid export. 3 unit tests including FR-spread proof.
- **Repo extractor — `wish-codegraph`.** Walks any directory, parses `Cargo.toml` (handles dotted-key shorthand like `foo.workspace = true`), recovers workspace-local inter-crate dep edges, projects to `Canvas` and `WorldPatch`. Verified on this repo: **78 crates, 3,309 files, 276 dep edges**. 4 unit tests.
- **Agent visualizer — `wish-agent-visualizer`.** `AgentRun` → `AgentDag` canvas + streaming `CanvasPatch` builder.
- **WorldLine ledger — `wish-provenance`.** Append-only JSONL provenance with `WorldEvent`, `apply_with_provenance(world, patch, auto_approve_max)`, `approve_pending`, risk-banded `ApprovalGate` (`Auto` / `HumanRequired` / `SimulationRequired`), deterministic Merkle root, branch support. 4 unit tests.
- **Hermon bridge façade — `wish-hermon-bridge`.** Stub `RoutingHint` model picker, lifted to the WWM layer. Replaced by a live `hermon_client` call in a later step.
- **Cell architecture — `wish-cell-runtime`.** `CellManifest`, `Capabilities`, `TrustTier`, `CellGate`, content-hash. Wasm sandbox itself stays deferred to v0.8.0. 5 unit tests.
- **Deterministic Shan Hai builder — `wish-world-studio`.** `build_shanhai_harbor` emits **seven** WorldPatches that, applied through `apply_with_provenance`, construct the demo region: World Architect agent → Dragon Temple → Merchant Liu → Banker Sun → Trader Wei → Risk-Master Chen → main scene. Every patch produces a signed `VerifiableArtifact` with structured `Evidence`. 2 unit tests.
- **`wish-world` CLI — `wish-world-cli`.** Subcommands: `inspect`, `canvas repo`, `canvas world`, `worldline`, `demo shanhai`, `view`, `tour`, `agent-dag`, `version`. Added to `default-members` so `cargo run --bin wish-world -- …` works from the workspace root. 4 end-to-end integration tests that spawn the binary.
- **Interactive browser canvas — `wish-world view` and `wish-world tour`.** `wish-world-studio::viewer` renders a self-contained dark-themed HTML viewer with pan/zoom (Fruchterman-Reingold layout), a clickable entity sidebar that two-way-binds to the SVG via `data-semantic-id`, and a collapsible WorldLine summary with risk score, approval state, actor, and intent. `wish-world tour` is the one-command experience: `cargo run --bin wish-world -- tour` builds the world, generates the viewer, and opens it in the system browser.
- **Native canvas render engine — `wish-render` + `wish-world render`.** A real OS window with GPU rendering of the Wish canvas, no browser involved. Built on `eframe` 0.29 (winit + wgpu + egui). Renders nodes as rounded rectangles tinted by `CanvasNodeKind`, edges as colored segments with arrowheads, labels with native text. Left-mouse drag pans, scroll-wheel zooms around the cursor, click selects (smallest-area-containing-point), sidebar entity click recenters the view. Auto-fits the bounding box on first frame. World inspector right-rail when a `WishWorld` is loaded. Three CLI subcommands: `wish-world render world <world-dir>`, `wish-world render repo <root>`, and `wish-world render demo` (the fastest path from `cargo run` to a real native window — builds the Shan Hai world in-memory, never touches disk). This is the v0.5.0 native render seam; the full direct-wgpu pipeline arrives in v0.6.0 as `wish-scene-renderer`.
- **3D scene canvas — `wish-render::scene3d`.** A toggleable 3D view inside the same native window. New `Camera3D` (orbit; yaw/pitch/distance/fov), self-contained `look_at` + perspective math (no glam/nalgebra), depth-sorted billboard rendering, ground grid (major axes highlighted), per-entity grounding stakes from the y=0 plane up to the entity position, scene-edge star wiring from `WorldScene::entity_ids`, depth-fog tint so distant entities recede, and click-to-pick within a 40-pixel screen radius. Auto-aims the camera at the world centroid when first entered. The toolbar gains a **🗺 2D canvas / 🌐 3D scene** segmented toggle (3D button disabled if no entity has a `Transform`). Drag = orbit; scroll = dolly. This is the first sprout of the v0.6.0 `wish-scene-renderer`; the math, picking, and centroid framing already work — v0.6.0 evolves the painter from egui's 2D primitive layer to a direct WGPU pipeline. 4 unit tests cover camera centroid, perspective projection, and screen-distance picking.
- **Time-travel + hot-reload — `wish-world timetravel` + `wish-world watch`.** Two new native-window modes that let humans (and external agents) observe a world's life across time. `WorldLine::replay_into(world, until_idx)` rebuilds the world deterministically by clearing its mutable collections and re-applying every event's patch up to the given index. `WorldLine::reload_if_changed` polls the file's mtime and reloads from disk when it grows — the seam for external Hermon agents writing patches that show up live in a running viewer. `wish-world timetravel <world-dir>` opens the viewer with a **scrub slider** in a new bottom panel (⏮ start / ⏭ now buttons, the current event's intent + risk + approval state shown alongside). `wish-world watch <world-dir> [--poll-ms]` polls and absorbs new events as they appear on disk; auto-refits the camera on growth until the user manually pans. 3 new unit tests in `wish-provenance` cover replay-zero, replay-N, and reload-detects-external-writes. Smoke-tested: launched the watcher on a 7-event Shan Hai world, an external `cat >> worldline.jsonl` appended a beacon entity, the viewer absorbed it within one poll interval.
- **Live two-process agent loop — `wish-world agent` + `wish-world watch`.** The full agentic-creation cockpit, in two cooperating CLI processes. `wish-world agent "<intent>" --target <world-dir> [--step-ms <n>] [--fresh]` seeds a fresh `.wishworld/` skeleton from an intent template (or wipes an existing target with `--fresh`), then **emits one WorldPatch per `step_ms`** through a real WorldLine on disk. Each patch is provenance-anchored and risk-scored just like any other agent's work. Run `wish-world watch <world-dir>` in another terminal and the native viewer absorbs each patch as it lands, animating the world's growth across two **independent OS processes**. Smoke-tested: the agent wrote 4 patches over 2.8s (temple → 4 bells → 3 pilgrims → main scene); the parallel watcher absorbed every event within one 250ms poll. This is the local-first equivalent of an external Hermon agent driving the Wish viewer in real time — and the seam that swaps the keyword matcher for a real LLM in v0.6.0 is the **same function signature** (`plan_world(intent) -> WorldPlan`).
- **Native canvas opens from inside the Wish app (no browser).** The three desktop-app palette actions — `Open Repo Canvas`, `Open Architecture View`, `Open Function Graph` — now **spawn the native `wish-world render` binary as a detached child process** instead of writing HTML and routing through `ctx.open_url()`. A new `try_spawn_native_render(perspective, root)` helper + `find_wish_world_binary()` lookup chain (env var `WISH_RENDER_BIN` → sibling of `current_exe()` → `$PATH` via `which`) reaches the binary in dev (`target/debug/wish-world`), in release bundles, and after `cargo install --path crates/wish-world-cli`. The browser-HTML viewer remains as a graceful fallback when no binary is installed — power users get the native window, casual users still get a working canvas. The spawned process runs with `stdin/stdout/stderr` piped to null so the Wish app doesn't capture its output. `CanvasPerspective::slug()` maps the palette enum to the `--perspective <name>` CLI flag, so `Open Architecture View` actually launches with `--perspective architecture` and the matching scientific-lens palette. The full integration roadmap (stage 1: spawn-as-child, today; stage 2: embedded pane v0.6.0; stage 3: codegraph in the editor v0.7.0) is documented in `wish-design/wish-plan-20260514/01-strategy/07-codegraph-in-the-ide.md`.
- **Cinematic boot — the wow moment.** Every `wish-world render` (demo / world / repo) and `wish-world build --live` now opens with a five-second introduction to the entire Wish-perspective system. **(1) Terminal splash** — a colored ANSI banner prints `✦ W I S H · the World Model IDE · v0.5.0 · 15 perspectives · The Tensorium` plus the 8 domain emojis and the 7 Tensorium-fundamental emojis, then the currently selected lens + tagline. Suppressible via `WISH_NO_SPLASH=1` (CI / tests / quiet smoke). **(2) Native-window cinematic** — when the eframe window opens, the canvas dims and a centered `✦ W I S H` title appears for 600 ms, then the viewer auto-cycles through **five representative lenses** (Engineering → Spatial → Financial → ∑ Math → ⚛ Physics, 700 ms each) with a soft pill at the top of the window labeling each. After ~4 s the cinematic settles on the user's chosen target perspective. Clicking or pressing any key dismisses immediately and locks in the target. New `BootState` (Splash / Cycling{step} / Done) + per-frame tick in `eframe::App::update`. New `boot_overlay` method paints the splash + pill on top of the canvas/scene via `egui::LayerId::new(Order::Foreground, …)` so it survives the 2D/3D mode toggle. The cinematic is the visible proof of the Tensorium thesis in the first user moment: same Shan Hai harbor world, five different lenses, no manual interaction. Smoke-tested with `cargo run --bin wish-world -- render demo` — terminal banner prints, native window opens with title, cycles through five perspectives, settles on Engineering.
- **The Tensorium — the multi-dimensional substrate is named, typed, and shipped.** Every Wish world now has access to a `Tensorium` — an N-dimensional coordinate space where every `SemanticId` can carry a position vector. AI lives in tensors natively; Wish gives that space a human-navigable interface. New `wish-world-model::tensorium` module ships `TensorAxis` (with `kind: TensorAxisKind` from {Spatial, Temporal, Categorical, Continuous, Latent, Frequency, Symbolic}, optional bounds, optional unit), `Tensorium` (axes + per-id row vectors), `add_axis` (auto-pads existing rows with NaN), `set_position`, `project_2d`, `project_3d`. 6 new unit tests cover axis-padding, NaN-skip projection semantics, unknown-axis safety, 3D triple projection, and full serde round-trip. The strategic frame lives at `wish-design/wish-plan-20260514/01-strategy/06-the-tensorium.md`: the Tensorium is what AI sees natively, and the 2D canvas + 3D scene + every domain perspective are just *projections* of it. v0.6.0 wires the renderer to consume Tensorium projections directly + adds an axis-selector UI for live re-projection; v0.7.0 adds non-visual semantic queries over the Tensorium for agents.
- **Seven scientific (Tensorium-fundamental) perspectives.** The Perspective system grows from 8 lenses to **15**, with the new `Math`, `Geometry`, `Chemistry`, `Physics`, `Linguistic`, `Geologic`, `Biologic` joining the existing domain lenses. These are the base disciplines from which every higher-order domain inherits — Engineering inherits from Math + Logic + Physics, Finance from Math + Game theory, Education from Linguistic + Biology + Cognitive science. Each scientific lens gets its own emoji label (`∑ Math`, `△ Geometry`, `⚗ Chemistry`, `⚛ Physics`, `🗣 Linguistic`, `🪨 Geologic`, `🧬 Biologic`), tagline, default layout, palette overrides keyed by Custom node-kind name (e.g., `atom*` is reddish, `particle*` is golden, `species*` is green, `stratum*` is earth-brown), and emphasized edge kinds (Math: Calls + DependsOn for proofs; Physics: Triggers + Produces + SucceededBy for causation; Linguistic: Mentions + SucceededBy for reply chains; etc.). The toolbar dropdown is now **grouped by category**: "— Domain —" header, the 8 domain lenses, separator, "— Science (Tensorium) —" header, the 7 scientific lenses. CLI slug aliases parse: `mathematics`, `chem`, `phys`, `chat`, `strata`, `ecology`. A new `PerspectiveCategory` enum (`Domain` | `Science`) drives the grouping. 4 new unit tests check the perspective count (= 15), category split (8 / 7), scientific-slug parse, and alias parse.
- **Domain perspectives — `wish-render::Perspective` + `--perspective <name>` + toolbar dropdown.** Eight first-class **lenses** on the same canvas: `Engineering`, `Architecture`, `Spatial`, `Financial`, `Education`, `Scientific`, `Design`, `Analytic`. Each perspective has its own default layout (force-directed / layered / grid), default view mode (the `Spatial` lens auto-enables 3D), kind-tinted color palette, emphasized edge kinds, and a one-sentence tagline shown beneath the dropdown so the user always knows what they're looking at. A new `egui::ComboBox` in the native-viewer toolbar lets users switch live — switching re-tints every node, re-runs layout, and snaps the view-mode to the perspective's default. New CLI flag `--perspective <slug>` works on `wish-world render demo|world|repo`; aliases like `eng`, `arch`, `finance`, `ux`, `data` are accepted. New desktop-app workspace actions `OpenArchitectureView` and `OpenFunctionGraph` join `OpenRepoCanvas`, each opening a perspective-flavored HTML viewer (the Architecture one renders Mermaid via the official CDN script, with the source diagram in a `<details>` for copy). `WorkspaceAction` enum extended; bindings registered in `app/src/workspace/mod.rs`; dispatched in `app/src/workspace/view.rs`. 6 new unit tests cover slug round-trip, alias acceptance, label/tagline non-empty for every perspective, `prefers_3d` exclusivity, and edge-emphasis correctness. Smoke-tested across `render demo --perspective {financial,spatial,education}` — all three launch with the correct lens label and the Spatial one defaults to 3D.
- **Multi-language codegraph — Rust + Python + TypeScript/JavaScript + Go.** Codegraph extraction is no longer Rust-only. New `wish-codegraph::languages` module ships hand-rolled, linear-time, line-based extractors for five languages — no regex, no tree-sitter dep, ~340 LOC. Each returns the same `ParsedFn { name, line, is_test, is_pub, is_async }` shape. **Rust**: `pub`/`pub(crate)`/`async`/`const`/`unsafe`/`extern "C"` `fn`, generics, `#[test]`-on-previous-line. **Python**: `def`, `async def`, `class`, with `@pytest.mark.*` decorator detection, `_private` convention, `test_*` naming. **TypeScript/JavaScript**: `function`, `export function`, `class`, `interface`, `type`, `const x = () =>`, `const x = async () =>`. **Go**: `func Name(`, `func (recv) Method(`, `type Name struct`, `type Name interface`, with the leading-uppercase-is-public Go convention and `Test*`/`Benchmark*` test detection. The walker dispatches by extension across `.rs`, `.py`, `.pyi`, `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.go`. 5 new unit tests cover all five languages plus the `Language::from_path` dispatch. The Calls heuristic still defaults to same-file (Rust only for now; cross-file resolution arrives in v0.6.0 via tree-sitter).
- **Architecture-view exporter — `wish-world canvas repo --format architecture-mermaid`.** The post-UML kingdom. A new `wish-codegraph::architecture` module rolls up a `RepoGraph` to one node per crate (with `files · fns · pub` sub-labels), groups by name prefix (`wish-*`, `wishui*`, etc.), and emits valid Mermaid `flowchart TD` notation that pastes into any Mermaid viewer (GitHub, docs, Notion, Slack). Auto-enables function extraction so sub-labels render. Three formats accepted: `architecture`, `arch`, `architecture-mermaid`, `arch-mermaid`. **The architecture diagram is now generated from the live codegraph every time, not hand-drawn and stale.** 3 new unit tests cover the rollup, the Mermaid emission, and the crate-grouping. Bigger picture: `wish-design/wish-plan-20260514/01-strategy/05-codegraph-post-uml.md` argues the codegraph is the *post-UML kingdom* — the alphabet of intent for vibe-coding agents and humans alike.
- **Function-level codegraph + `Calls` edges — `wish-world canvas repo --functions`.** The repo canvas is now a real code-graph, not just a file map. `wish-codegraph` ships an `ExtractOptions::with_functions(true)` knob plus a hand-rolled Rust-only function extractor that handles `pub`, `pub(crate)`, `async`, `const`, `unsafe`, `extern`, `extern "C"` qualifiers, multi-line signatures, `#[test]` annotations, and skips commented-out lines. Each discovered function becomes a `code:function:<crate>::<file_stem>::<name>` SemanticId in the world model and a labelled node in the canvas (`test` kind for `#[test]` fns, otherwise `Function`). The `Calls` edge heuristic uses a fast same-file scan (default; configurable via `ExtractOptions::with_same_file_calls_only(false)` for the slower global-uniqueness path). File-text caching cut full-repo function extraction from O(functions × global names) to O(files × intra-file functions²). 4 new unit tests cover signature parsing, word-boundary mention detection, balanced-brace body extraction, and a live-crate sanity check. Verified on `wish-canvas-core`: 6 files → 32 functions + 22 call edges.
- **Wish-aware terminal blocks — `wish-world block "<shell-cmd>" --target <world-dir>`.** Run a shell command through `$SHELL -c`, capture stdout / stderr / exit code, and write the result as a `TerminalBlock` `WorldEntity` with a stable `terminal:block:<key>-<nanos>` SemanticId. The captured output becomes a `Component::Custom` payload (started_at, finished_at, exit_code, shell, argv, stdout, stderr — truncated to 4 KiB each). The patch is anchored by the human user (`Actor::Human { user_id: $USER }`), runs through `apply_with_provenance` with the normal risk gate, and lands in the WorldLine. **Your shell history becomes a provenance-anchored part of the world model** — `wish-world worldline` displays each terminal block with intent, actor, and event id. Bug fixed in passing: `write_world_dir` was overwriting `worldline.jsonl` from the slim `world.provenance` field; now it only seeds on initial write, since `wish-provenance` owns the JSONL.
- **Repo-watch — `wish-world repo-watch <root> --target <world-dir> [--poll-ms <n>] [--functions]`.** A long-running watcher that walks a codebase, computes a (crates, files, deps, functions, calls) signature, and emits a snapshot WorldPatch every time the signature changes. Pair with `wish-world watch <world-dir>` in another terminal to mirror a real codebase into the native viewer live as you edit. Each tick logs the new shape; the underlying patch is gated through `apply_with_provenance` at a loose threshold so the bulk snapshots flow through without piling up in the approval queue.
- **Multi-agent swarm — `wish-world swarm "<intent>" --count N`.** N concurrent agents collaborate on building one world. Patches from the intent template are partitioned round-robin across the agents, each runs in its own OS thread, all share one `Arc<Mutex<WorldLine>>` + `Arc<Mutex<WishWorld>>` so the WorldLine appends serialize cleanly. Each agent prefixes its log lines with `[agent-i]`. Pair with `wish-world watch` in another terminal for a live two-process N-agent swarm. Smoke-tested: 3 agents emitted 7 patches into one Shan Hai WorldLine over 2.1s, interleaved cleanly, watcher absorbed every event within 250ms.
- **WorldLine branching — `wish-world branch` / `wish-world branches`.** Git-for-AI-generated-worlds. New `WorldLine::branch_from(name, from_event_id)` writes a provenance-anchored `branch_from` marker and switches the active branch; `switch_to(branch)`, `current_branch()`, `branches()`, and `count_on(branch)` round out the API. All subsequent `apply_with_provenance` calls tag their events with the current branch. `wish-world branches <world-dir>` lists every branch with event counts and a `*` for the active one; `wish-world branch <world-dir> <new-branch> [--from <event-id>]` forks. 2 new unit tests cover the fork + switch flow and the unknown-parent rejection. Smoke-tested end-to-end: built a temple on `main` (4 events), forked an `experiment` branch, agent added 4 more on experiment (5 events including marker), `branches` correctly lists both with `* experiment` as current.
- **Intent → World, animated live — `wish-world build "<intent>"`.** The "type a prompt, watch a world materialize natively" demo. New `wish-world-studio::intent::plan_world(intent)` keyword-matches the prompt against four templates (Shan Hai harbor; Mythic Dragon Temple with four ritual bells and three pilgrim NPCs; Service Topology with gateway + API + 3 workers + datastore; Education World with teacher + three students) and returns a `WorldPlan` — a starting world plus an ordered `Vec<WorldPatch>`. `--live` opens a native window via the new `wish_render::run_live(plan, step_delay)` that applies one patch per tick, re-projects the canvas, and auto-fits the bounding box as the world grows. Toolbar gains a `step N/M` indicator plus `⏸ pause` / `▶ resume` / `⏭ all` buttons. Patches flow through a real WorldLine in a temp dir, so the right-rail inspector updates as the build progresses. Without `--live`, the headless path applies all patches synchronously, writes the `.wishworld/` to disk (or `--out <dir>`), and prints next-step hints. 5 unit tests cover the four templates plus end-to-end `apply_plan` round-trip. The keyword matcher is the v0.5.0 stand-in for a Hermon LLM call; the renderer + provenance + world model don't change when v0.6.0 swaps the matcher for a real model.
- **Desktop app surface — `FeatureFlag::WishCanvas2D` + `WorkspaceAction::OpenRepoCanvas`.** Gated by the new flag (on in dogfood). Command palette gains `Open Repo Canvas (Wish World Model)` keybound to `workspace:open_repo_canvas`. When invoked it walks the active project via `wish-codegraph`, renders the canvas to a temp HTML file via `wish-world-studio::canvas_html`, and opens it in the system browser using the same `ctx.open_url()` path as `Join Slack`. First visible bridge from the v0.4.0 desktop app to the v0.5.0 substrate.
